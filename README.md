# mimesis

> μίμησις — 모방은 학습의 가장 오래된 형태다.

대표 인물의 사고방식과 삶의 태도를 해체하고, 내 것으로 체화하기 위한 개인 학습 저장소.

## 왜 만들었는가

읽고 감탄하는 것에서 멈추면 아무것도 남지 않는다.
거장의 결과물이 아니라 **사고의 골격**과 **삶의 운영 원칙**을 추출해, 내 일과 삶에 옮겨 심는 것이 목표다.

- **사고법(How they think)** — 맥킨지식 문제 정의, 파인만의 학습법, 찰리 멍거의 멘탈 모델
- **태도(How they live)** — 이어령의 지적 호기심, 스티브 잡스의 단순함, 세네카의 평정
- **작업법(How they work)** — 헤밍웨이의 글쓰기 루틴, 다 빈치의 노트, 폰 노이만의 문제 분해

## 디렉토리 구조

```
mimesis/
├── people/                  # 인물별 폴더
│   ├── mckinsey/            # 사고 프레임워크 (MECE, Pyramid Principle, SCQA)
│   ├── lee-eo-ryeong/       # 삶의 태도와 지적 호기심
│   └── <name>/
│       ├── profile.md       # 누구인가 / 왜 배우는가
│       ├── principles.md    # 핵심 원칙
│       ├── methods/         # 구체적인 방법론
│       ├── quotes.md        # 원문 인용 (출처 필수)
│       └── practice.md      # 내 일상에 적용한 기록
├── patterns/                # 인물을 가로지르는 공통 패턴
└── reflections/             # 적용 후 회고
```

## 작성 원칙

1. **요약하지 말고 해체하라** — "뭐라고 말했는가"가 아니라 "어떤 구조로 사고했는가"를 적는다.
2. **출처를 남겨라** — 원문/페이지/영상 타임스탬프. 검증되지 않은 명언은 받아들이지 않는다.
3. **적용 없이는 완성이 아니다** — 모든 원칙은 `practice.md`에 실제 적용 기록이 따라붙는다.
4. **회의하라** — 거장도 틀린다. 동의하지 않는 지점은 `reflections/`에 명시한다.

## 사용법

새 인물을 추가할 때는 `people/<name>/profile.md`부터 시작한다.
profile에는 **왜 이 사람을 배워야 하는가** 한 문단을 반드시 적는다. 이유가 약하면 추가하지 않는다.
